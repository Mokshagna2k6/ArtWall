# Refactor changelog — 2026-10-21

A structural and documentation cleanup. **No application code was moved and no
behavior was changed.** Every source-file edit in this change is a comment or a
path string; the only non-comment edit is one ESLint ignore glob that had to
follow a moved directory.

Branch: `review/all-phases`.

---

## 1. Why the application structure was left alone

The audit that preceded this change looked for architectural problems and did
not find the ones that had been expected. Before any change, the baseline was:

| Check | Result |
| --- | --- |
| `pnpm typecheck` | 0 errors |
| `pnpm lint` | 0 errors, 32 warnings |
| `pnpm test` | 718 passing (694 in `apps/web` over 49 files, 24 in packages) |
| `pnpm build` | Succeeds |

`apps/web` is a coherent, feature-sliced App Router application. `packages/db`,
`packages/security`, `packages/ratelimit` and `packages/cache` are real
packages with their own tests and a strictly one-way dependency graph. CI runs
seven jobs including gitleaks over full history, a high/critical dependency
audit, an idempotent-migration check and Foundry contract tests. No secret is
tracked and none appears anywhere in git history.

Given that, moving source code would have carried risk with no demonstrated
benefit, so it was not done. The real problems were all in the repository root
and the documentation layer. What *was* considered and rejected is recorded in
[`ARCHITECTURE_DECISIONS.md`](ARCHITECTURE_DECISIONS.md), in particular the
request for separate `frontend/` and `backend/` directories (section 2 — the
split already exists, enforced by `server-only`, and a folder split would break
App Router route discovery).

## 6. Deliberately not done

| Item | Why |
| --- | --- |
| **Pruning the 52 git worktrees in `.claude/worktrees/`** | They are *registered* worktrees on named branches that may hold unmerged commits or uncommitted work. Removing them is destructive and is the repository owner's decision. To review: `git worktree list`, then per directory `git -C <dir> status --short` and `git -C <dir> log --oneline main..HEAD`. Only then `git worktree remove <dir>` and `git worktree prune`. |
| **Deleting any document** | Several archived documents are the only written record of why shipped code looks as it does. Archiving preserves that; deleting would not. |
| **Renumbering migration `0057`** | Both files are applied. Renumbering an applied migration is riskier than the cosmetic confusion it would fix. |
| **Populating `apps/api/` or `packages/shared/`** | Creating a workspace because the directory exists would be architecture-by-appearance. See `docs/plans/PRODUCTION_SCALE_PLAN.md`. |
| **Resolving the SES-vs-Resend and Privy-vs-wagmi conflicts** | Both are recorded with the code named as authoritative. Changing either is a product decision. |
| **Fixing the 32 lint warnings** | They mark intentional stubs. Silencing them would hide those stubs. |
| **Any dependency change** | Out of scope for a structural cleanup. |

## 7. Still open

Carried forward from the archived audits and re-verified during this change,
so none of it is lost now that those documents have moved:

1. **No row-level security.** `packages/db/rls/` is a README only. Authorization
   is application-code only, with no database-level second line of defense.
   The most significant open architectural risk — see
   [`ARCHITECTURE_DECISIONS.md`](ARCHITECTURE_DECISIONS.md) section 7.
2. **Escrow is schema-only.** Tables exist (`0049`, `0057`); nothing writes them.
3. **`PolicyEngine` partly wired.** `canMint` has a real call site;
   `canList` and `canSecondarySell` have none.
4. **Sponsors and Events/Workshops** — the v1.1 audit found both entirely
   missing. Not re-verified during this change; treat as open.
5. **Two admin surfaces with different auth models** —
   `/physical-wall/admin` (role-based) and `/admin/tiles` (shared password).
6. **`HANDOFF.md` is untracked** and reports a buyer purchase flow as absent,
   while recent commits add "Buy and save" to listing cards. Worth re-checking
   and committing, as it is the entry point for the next person.
